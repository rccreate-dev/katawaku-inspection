## ユーザー判断が必要な点(実装前に決める)

1. **初期のactive項目をどうするか(最重要)**。現行テスト一式は「active=16項目(i1〜i16)」を前提にしている。
   - 案A: **active 16 はそのまま**。元Excel由来の落ち項目(c)は `active=FALSE` の新規行(i32〜)として追加するだけ。テストへの影響ほぼ無し。現場では責任者が有効化。
   - 案B: **元Excelの項目を active に入れる**(例: スリット・目地・かぶり等を有効化)。active 件数が変わり、e-4 のとおり契約テスト・シード・SPEC §11.5/§12 を一斉に更新する必要がある(テスト担当の作業が大きい)。
   - 現SPECは「プロトタイプの16を active」「元Excel非対応9件が active」としているので、案Aでも「元Excelに無い項目が現場の初期画面に出て、元Excelにある項目が出ない」状態は残る。この点が問題なら案Bを検討。
2. **audience の扱い**: 元Excelは職長用/管理者用でシートが別。(d-3)のとおり SPEC は全 both。元Excel通りに `foreman`/`qa` を使うか、現行どおり both か。(c) の行案は元シート由来で audience を提案したが、both に倒すこともできる。
3. **全数/抽出の保持場所**: Items に該当列が無い。①項目の `note` に書くだけ(運用メモ)、②SPEC変更要望として Items に列(例 `sampling`)を追加、③ルールを設定値にする(REQUIREMENTS §5「寸法=代表実測」は measure/minMeasures で既に表現済みで、管理者の「抽出」は運用に任せる)、のいずれか。いずれもSPEC変更になるものは設計担当への「SPEC変更要望」。
4. **統合の粒度**: i6(開口2→1)・i16(清掃4→1)・i17(かぶり3→1)など、原紙1行を1項目にまとめたままにするか、原紙どおり分けるか。分けると active 件数・テストに影響(判断1と連動)。
5. **i4 の文言**(d-2): 「柱・壁」を「外部型枠」に直すか、原紙にはない柱・壁の建入れとして残して外部型枠の建入を別項目にするか。
6. **i7 の許容5mm**(d-1): 原紙に無い。残すか、tol を空にするか(テストの i7 依存は無いが、SPEC 変更が必要)。
7. **管理者⑧「固め状況」の意味**(ユーザーまたは現場責任者への確認事項)、**⑬⑭ 出来形の段階**(打設前シートにあるが打設後の確認)。
8. **インドネシア語**: (c) の訳はすべて暫定。ネイティブ確認(P-22)が必要。特に「目地棒」「ダメ穴」「KY用紙」「固め」。
9. **REQUIREMENTS §10「追加提案34項目」の数え方**を確認し、SPEC/REQUIREMENTS の記述を揃える。
10. **突合結果の反映先**: SPEC §2.6.1・§11.5・§12 と REQUIREMENTS §10 の更新は設計担当/メインの担当(CLAUDE.md §1)。本書は docs/ 配下の参考資料で正本ではない。
